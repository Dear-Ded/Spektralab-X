## User-facing release notes

Follow `docs/RELEASE_NOTES_POLICY.md` for `CHANGELOG.md`, fastlane changelogs,
release bodies and in-app update summaries, including edits to historical entries.
Use plain language and describe concrete features, fixes and improvements to use.
Never include developer identities, local paths, private device details, cloud
providers, machine names, test environments, workflow runs or internal test logs.
Keep implementation and validation evidence in engineering records, with private
evidence outside Git. Preserve honest release status and material user limitations.
Do not publish or modify an existing GitHub release without the user's authorization.
