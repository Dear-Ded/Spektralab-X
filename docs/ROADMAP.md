# 路线图 / Roadmap

所有需求按里程碑排列。每个里程碑先定目标和验收标准，按顺序推进，完成一项勾掉一项。

**规则**

- 每项功能动手前先调研外部成熟做法，调研结论记在对应条目下，再按本项目情况适配。调研完成前不写代码。
- 版本号只加修订号（`0.1.x-alpha`），能日常使用之前都是 alpha。
- “完成”指已提交且 CI 通过；“已验证”指在真机上确认过。两者分开记。
- 状态标记：`[x]` 完成，`[~]` 进行中，`[ ]` 未开始，`(真机待验)` 已完成但未在手机上确认。
- **能预设的都预设。** 开源项目开箱即用：每个可配置的地方都附带一套可直接用的默认值和示例，用户只在想改时才需要动手。随仓库附带的预设必须许可干净（注明来源和许可，能再分发），不能再分发的只给下载链接或说明。

## M1 真机反馈修复 → `0.1.19-alpha`

目标：修掉第一次真机试用发现的问题。验收：用户在真机上确认四项都不再出现。

- [x] 颜色不正：打开参数与桌面版对齐（Supra Endura、均衡测光、40 CC 滤镜刻度、手机照片测光、黑白滤镜组）(真机待验)
- [x] 没有保存按钮：顶栏加“保存” (真机待验)
- [ ] 指引位置不对：空白页改为居中“打开照片”按钮（已完成），并做首次使用引导（见 M3）
- [ ] 界面素、流畅度和切换动效不足（见 M3）
- [~] 色彩对照测试：同几张 RAW 在桌面版和安卓版用同样参数导出，算 ΔE00，平均值低于 1 才算还原
  - 第一轮（2026-11-03，云主机 lavapipe，`tools/parity`，颗粒和眩光关闭，RAW 沙丘与合成色卡，Portra 400 / CineStill+2383 / Velvia / Tri-X）：新导出路径直接用上游 `output.cpp` 的转换代码，与上游导出一致。旧安卓路径与上游导出相比平均 ΔE00 0.02–0.09，但最饱和的 0.1% 像素达 3.6–7.0，最大 22（色卡高饱和色块）；黑白胶片几乎为 0。屏幕路径（矩阵加裁切）与导出平均差 0.13–0.22，这是上游自己屏幕与导出之间的差别。显示用的查找表与精确曲线最大差 0.001。
  - 结论：旧路径平均已很接近，偏差集中在高饱和色；真机上“颜色不正”的主因更可能是之前修掉的参数差异和没开广色域。
  - 还缺：用上游 Linux 版 `spektralab-host` 的 `export_frame` 做独立参照（目前参照是编进本项目的上游代码）；在 Adreno 真机上跑同一组对照；P3 目标的对照。

  - 需要补的能力：参数曲线（趾部 / 肩部 / 枢轴，查表实现，最优先）；按色相的肤色保护与肤色色偏（注明“按色相”，不是人脸识别）。景深类（蔡司焦外、Harcourt 布光）不做。

## M4 远程处理 → 正式版（不进 alpha）

目标：留出统一的接口和服务模块，让用户把照片交给自己的电脑或服务器做预置后处理或大模型后处理，处理完传回手机。这是资深用户扩展的主要入口。

**排期（2026-11-03 决定）：alpha 阶段只保留调研和接口规范，不实装。参考服务端、手机端和配置指南放进正式版的更新计划，等 M1–M3、M5 完成、真机验证通过后再开工。** alpha 版本不加网络权限，“不联网、照片不离开手机”的承诺保持不变。

- [x] 调研：接口协议、配对与安全、服务器配置 / 环境 / 应用、大模型后处理方案（类似“徕卡一瞬”的思路）
  - 接口协议：参考服务端包装上游桌面版的 `export_frame`（引擎无需改动）；HTTPS，扫码配对并固定证书指纹；原图按 SHA-256 分块断点上传；任务由服务器保管，手机被杀后可再查询；后处理脚本只能在服务器配置里登记，手机按名字选择，不能下发脚本。
  - “徕卡一瞬”本身是拍摄时在手机上完成的固定色调（M9 / M3 Monopan 50 两种），不是云端或大模型处理；我们的引擎已经在手机上做这一类。远程模块对应的是三星、谷歌放到云端的那一层（修复、放大、生成式编辑），区别是跑在用户自己的 GPU 上。

## M5 架构与稳定性 → 随各版本推进

目标：大图不闪退、不卡编辑器、被系统杀掉也不丢东西。

- [ ] 导出时编辑器不卡顿（导出与编辑共用一个引擎线程的问题）
- [ ] 内存预算：按 Android 17 每应用内存上限设计，导出分块，按峰值内存而不是 PSS 计量
