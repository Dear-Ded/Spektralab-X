# UI 2.0 问题优先级诊断

> 生成时间：2026-11-08  
> 状态：诊断完成，待修复  
> 依据：UI2.md 6.1-6.3 进度、UI2_RESEARCH.md 调研、用户反馈"各 UI 还存在很大问题"

## 0. 诊断方法

按三个维度评估：
1. **用户体验影响**：是否影响核心交互流程（编辑照片、切换参数、保存导出）
2. **视觉一致性**：是否与 UI 2.0 规范（UI2.md）冲突
3. **响应速度**：是否造成卡顿、掉帧、延迟感知

每个问题标注：
- **验收标准**：怎样算修好
- **用户价值**：解决后用户得到什么
- **技术归属**：哪个分支/文件负责

## 1. 🔴 P0 级：影响核心交互，必须立即修复

### 1.1 预测性返回缺失 — 返回手势不跟手

**现状问题**（UI2.md 6.1 line 268）：
- 底部面板展开时按返回键，面板不跟手势收起，直接跳回上一级
- 1:1 查看、单张查看返回时没有手势预览，用户无法预判返回结果
- 编辑器返回观片台时是硬切，没有淡入淡出

**用户影响**：
- 手势反馈断裂，不符合"跟手"承诺（UI2.md 0 节用户反馈）
- Android 14+ 系统级特性缺失，显得落后

**验收标准**（UI2.md 3.8）：
- 底部面板展开时，返回手势让面板跟手往下收，最多收到少一档；松手吸附或取消
- 1:1 查看时，返回手势让整屏缩到 90%、边距 8 dp、向手势反方向偏移；松手退出或取消
- 单张查看→网格：照片跟手缩小，松手后共享元素飞回格子
- 编辑器→观片台：编辑器缩到 90% 淡出，观片台从 110% 缩回 100% 淡入

**用户价值**：
- 每次返回操作都有实时预览，手指离开前就知道会回到哪里
- 符合 Android 14+ 系统习惯，减少误操作

**技术归属**：
- `Interactions.kt`：`rememberBackProgress()` + `Modifier.predictiveBackScale(...)`
- `LightTableNav.kt`：`SeekableTransitionState` 驱动整屏切换
- 分支：ui-motion（尚未提供，UI2.md 6.2 line 278）

---

### 1.2 面板无法上拉到 3/4 高度 — 显示区域受限

**现状问题**（UI2.md 6.1 line 268）：
- 底部面板只有两档高度（收起、半屏），无法拉到 3/4 屏
- 长列表内容（风格卡片、调整项）需要在半屏内滚动，照片被遮挡过多

**用户影响**：
- 查看更多选项时，照片可见区域太小，无法同时看效果和选项
- 拖动面板到合适高度后松手会回弹，无法停在想要的位置

**验收标准**（UI2.md 3.7, 2.3）：
- 面板支持三档高度：收起（工具栏可见）、半屏（约 50%）、3/4 屏（留照片 1/4）
- 拖动时 1:1 跟手，松手按位置和速度吸到最近一档
- 快速甩动可多走一档（半屏→3/4 屏）

**用户价值**：
- 长列表（87 款胶片、调整项）可以在更大区域浏览
- 照片仍保留可见区域，不会完全被遮挡

**技术归属**：
- `EditorScreen.kt`：面板容器的 `Modifier.offset` + 吸附逻辑
- `Interactions.kt`：`defaultSpatial` 弹簧，带松手速度
- 分支：ui-motion

---

### 1.3 共享元素转场缺失 — 卡片切换生硬

**现状问题**（UI2.md 6.1 line 268）：
- 点击风格/胶卷卡片进入强度面板时，是硬切换，没有卡片"长成"面板的动画
- 观片台网格缩略图→单张查看时，照片是淡入，不是从格子位置飞出来
- 单张查看→编辑器时，照片位置跳变

**用户影响**：
- 视觉连续性断裂，不知道当前面板从哪来
- 不符合"丝滑"承诺，转场感觉廉价

**验收标准**（UI2.md 3.7）：
- 风格/胶卷卡片→强度面板：卡片的圆角容器长成面板（`sharedBounds`），文字淡入，`defaultSpatial` 弹簧
- 观片台网格→单张查看：缩略图的位置和大小长到全屏，背景从 0 淡到不透明，`slowSpatial` 弹簧
- 单张查看→编辑器：照片原位不动，周围的面板从下往上进来，`defaultSpatial` 弹簧

**用户价值**：
- 每次切换都能看清楚"从哪来到哪去"
- 卡片和面板之间的关系一目了然

**技术归属**：
- `SharedTransitionLayout` 包裹相关页面
- `Modifier.sharedBounds(...)`、`Modifier.sharedElement(...)`
- 分支：ui-motion

## 2. 🟡 P1 级：影响视觉一致性，需尽快修复

### 2.1 观片台/设置/正在处理页面布局未重排

**现状问题**（UI2.md 6.1 line 268）：
- 这些页面只换了配色和选中样式，布局仍是旧版
- 圆角、间距、字重、按钮样式与编辑器页面不一致

**用户影响**：
- 从编辑器切到设置页，视觉风格突变
- 观片台的卡片圆角、间距与编辑器里的风格卡不统一

**验收标准**（UI2.md 1, 6.2）：
- 观片台：网格卡片改用 `ThumbCard`（104 dp 方图 + 白环选中）
- 设置：每行改用 `SettingRow`（整行开关 + 白轨黑点）
- 正在处理：进度条改用中性白色（已在 ui-neutral-colors 完成 JobNotifier.kt）
- 导入页：卡片圆角统一 12 dp，按钮改用 `QuietButton` / `TonalButton`

**用户价值**：
- 全应用视觉风格统一，不会在不同页面感到"割裂"

**技术归属**：
- `LightTable.kt`、`SettingsScreen.kt`、`QueueScreen.kt`、`ImportSheet.kt`
- 分支：ui-screens

---

### 2.2 按压/弹簧修饰符未统一

**现状问题**（UI2.md 6.2 line 278）：
- 组件里暂用现有的 0.95-0.96 按压缩放
- 应该用 `Interactions.kt` 提供的 `Modifier.pressScale(...)` 和 M3 Expressive 弹簧数值

**用户影响**：
- 不同控件的按压反馈不一致（有的缩 0.95，有的缩 0.96）
- 弹簧参数不统一，动画速度不一致

**验收标准**（UI2.md 3.6, 3.2）：
- 所有可点击控件改用 `Modifier.pressScale(interactionSource)`，按下缩到 0.96
- 选中状态改用 `rememberSelectionStyle(selected)`，圆角从 12 dp 变到全圆用 `fastSpatial` (0.6/800)
- 面板、卡片移动用 `defaultSpatial` (0.8/380)

**用户价值**：
- 每个按钮的反馈手感一致
- 动画速度统一，不会有的快有的慢

**技术归属**：
- `Pill.kt`、`Styles.kt`、`EditorScreen.kt` 等所有组件文件
- 依赖 `Interactions.kt`（ui-motion 提供）
- 分支：ui-visual → ui-motion

## 3. 🟢 P2 级：优化体验，排在 P0/P1 之后

### 3.1 风格条最前面缺"原图"卡

**现状问题**（UI2.md 6.2 line 278, 7.2 第 5 条）：
- 相纸条有"直接扫描"，边框条有"无边框"，但风格条没有"原图"
- 用户想取消风格时，只能重置全部或进修改记录删除

**用户影响**：
- 套错风格后，无法一键回到原图
- 不符合醒图的 ⊘ "无"设计（上游 issue #31）

**验收标准**（UI2.md 7.2 第 5 条）：
- 风格条最前面加"原图"卡（⊘ 图标 + "原图"文字）
- 点击后进入"不套风格"状态，胶片、相纸、调整层仍保留

**技术障碍**：
- 要改 ViewModel，现在没有"不套风格"的编辑状态
- 记为待办，不在这一轮范围（UI2.md 6.2）

**用户价值**：
- 一键回到原图，试验风格更自由

**技术归属**：
- `EditorViewModel.kt`：加 `StyleState.None` 状态
- `Styles.kt`：风格条头部加"原图"卡
- 分支：待定（需主会话决定）

---

### 3.2 曝光/放大曝光未改刻度尺控件

**现状问题**（UI2.md 6.5 line 300）：
- 曝光、放大曝光仍是普通滑杆
- 应该改成刻度尺式控件（1/3 EV 一格、固定中心指针、白色刻度、每格 Segment 震动）

**用户影响**：
- EV 档位不够精确（普通滑杆是连续值）
- 没有每 1/3 档的触感反馈

**验收标准**（UI2.md 6.5）：
- 新写 `ExposureDial` 组件：横向刻度尺，中心固定指针，数值浮在指针上方
- 每 1/3 EV 一格，拖过一格震动一次（`HapticEvent.Segment`）
- 点击 ±0.3 按钮单步调整，双击归零

**技术障碍**：
- 新控件要核对与现有点击步进、双击归零、数值输入的关系
- 留到截图流水线出来后一起看（UI2.md 6.5）

**用户价值**：
- 曝光调整更精确，符合摄影习惯
- 每档有触感，盲操作也能数格子

**技术归属**：
- 新组件 `ExposureDial.kt`
- `AdjustPanel.kt`：替换曝光滑杆
- 分支：待定（ui-screens 或单独分支）

---

### 3.3 开屏动画仍不够丝滑

**现状问题**（UI2_RESEARCH.md 11.1，已在 ui-neutral-colors e6149ea 研究）：
- 总时长约 1 秒（光晕 0-500ms，光谱 0-450ms，sprocket 60-600ms，名称 200-900ms）
- 引擎预热快时，动画被截断，名称还没落完就退出了
- 没有沉浸感，用户反馈"一闪而过"

**用户影响**：
- 启动体验草率，不符合"沉浸感、丝滑"承诺
- 名称分屏瓦片（SplitFlap）动画还没看清就结束了

**优化方案**（UI2_RESEARCH.md 11.2）：
- 延长最小停留时间到 1000 ms（当前 600 ms）
- sprocket pull 动画用 `slowSpatial` (0.8/200) 代替当前的线性插值
- 名称完成后渐进退出（淡出 + 轻微上移），不要硬切

**验收标准**：
- 开屏动画总时长 1.0-1.6 秒
- 即使引擎预热很快，名称也能完整展示
- 退出时淡出 300ms + 上移 8dp

**用户价值**：
- 启动时有仪式感，不会匆忙
- 名称（Spektralab-X）清晰可见，品牌印象深刻

**技术归属**：
- `LaunchIntro.kt`：调整时长和弹簧参数
- 分支：ui-neutral-colors（已研究）或 ui-motion（实施）

---

### 3.4 React Bits 动效未集成

**现状问题**（UI2_RESEARCH.md 12，已在 ui-neutral-colors e6149ea 研究）：
- 已采用 SplitFlap 和 Aurora（MIT + Commons Clause）
- 还有适合的组件未用：Pixel Transition（胶片风格切换）、Lattice Loader（处理队列指示）

**用户影响**：
- 切换胶片时是简单淡入淡出，没有"胶片感"
- 处理队列的加载动画是普通圆环，不够特别

**优化方案**（UI2_RESEARCH.md 12.2）：
- Pixel Transition：用于风格/胶片切换，像素块扫过的电影感
- Lattice Loader：用于"正在处理"页面，网格脉冲动画

**验收标准**：
- 风格/胶片切换时，照片用 Pixel Transition 过渡（300-500ms）
- 正在处理页面的加载指示用 Lattice Loader

**技术障碍**：
- reactbits.dev 的组件是 React/Framer Motion，需要翻译成 Compose
- 许可证 MIT + Commons Clause，允许使用但不能转售

**用户价值**：
- 切换更有"胶片模拟"的氛围感
- 处理动画更精致

**技术归属**：
- 新文件 `PixelTransition.kt`、`LatticeLoader.kt`（移植 React Bits）
- `Styles.kt`、`QueueScreen.kt`：使用新组件
- 分支：ui-motion 或 ui-effects

### 4.2 修改记录的"临时隐藏这一组"未做

**现状问题**（UI2.md 6.5 line 299）：
- 修改记录可以列出改过的组、点一行回到那一步、单组重置
- 但不能"临时隐藏这一组"（Snapseed 的功能）

**用户影响**：
- 想对比"加颗粒"和"不加颗粒"时，只能撤销或重置，不能临时关闭

**技术障碍**：
- 需要 ViewModel 提供"只渲染、不进撤销历史"的预览入口
- 等主会话决定归属（UI2.md 6.5）

**用户价值**：
- 快速对比某一组调整的前后效果

**技术归属**：
- `EditorViewModel.kt`：预览模式
- `HistorySheet.kt`：临时隐藏开关
- 分支：待定

## 5. 总结：修复顺序

### 第一批（P0，阻塞"丝滑"承诺）：
1. **预测性返回** — 每次返回都跟手，符合 Android 14+ 习惯
2. **面板 3/4 高度** — 长列表可见，照片不被完全遮挡
3. **共享元素转场** — 卡片"长成"面板，视觉连续

### 第二批（P1，视觉一致性）：
4. **其他页面重排** — 观片台、设置、正在处理统一风格
5. **按压/弹簧统一** — 全应用动画手感一致

### 第三批（P2，体验优化）：
6. **开屏动画延长** — 名称完整展示，沉浸感
7. **React Bits 集成** — Pixel Transition 胶片感，Lattice Loader

### 第四批（P3，长期）：
8. **截图自查**
9. **修改记录增强**

## 6. 每个问题的用户价值总结

| 问题 | 用户得到什么 | 失去什么（如果不修） |
|---|---|---|
| 预测性返回 | 每次返回前预览目标，减少误操作 | 返回操作不跟手，显得落后 |
| 面板 3/4 高度 | 长列表+照片同时可见 | 照片被遮太多，或列表滚动费劲 |
| 共享元素转场 | 卡片到面板的关系清晰，"从哪来" | 硬切换，视觉断裂 |
| 其他页面重排 | 全应用风格统一 | 设置/观片台像"旧版"，割裂感 |
| 按压/弹簧统一 | 每个按钮手感一致 | 动画速度乱，有的快有的慢 |
| 开屏动画延长 | 启动有仪式感，品牌印象深刻 | 一闪而过，草率 |
| React Bits 集成 | 切换有"胶片感"，处理动画精致 | 普通淡入淡出，平淡 |
