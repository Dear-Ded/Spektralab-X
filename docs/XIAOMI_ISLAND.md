# 小米超级岛 / 焦点通知：现状与申请材料

> **决定（2026-11-05）：不上架任何应用商店。** Spektralab-X 是开源项目，只在 GitHub Releases 发布。因此不申请小米超级岛官方权限，进度通知继续走 Android 标准实时通知（Live Updates），澎湃OS 上照样会显示在焦点通知区。以下内容留作记录。

> 状态（2026-11）：**未申请**。导出进度走 Android 16 标准实时通知（Live Updates），HyperOS 3 起系统会把它放进超级岛；同时附带小米焦点通知参数（`miui.focus.param`，协议 1），没有小米授权时系统按普通通知显示，不会丢。

本文是向小米申请焦点通知 / 超级岛权限时要准备的东西。来源：小米 HyperOS 开发文档（dev.mi.com）的焦点通知开发指南、超级岛接入流程和常见问题，以及阿里云 EMAS《小米超级岛推送指南》。小米随时可能改流程，申请前以 dev.mi.com 为准。

## 1. 应用里已经做了什么

| 项 | 做法 | 代码 |
|---|---|---|
| 主路径 | Android 16 实时通知：`ProgressStyle`、常驻、`setRequestPromotedOngoing(true)`、状态栏短文本（剩余时间） | `JobNotifier.build` |
| 焦点通知参数 | `miui.focus.param`（`param_v2`，`protocol: 1`，`filterWhenNoPermission: false`），含岛的大小区域 | `JobNotifier.focusExtras` |
| 支持与权限检查 | 启动时后台线程读 `Settings.System` 的 `notification_focus_protocol`（1/2/3 = OS1/OS2/OS3 模板版本）和 `content://miui.statusbar.notification.public` 的 `canShowFocus`，只记进诊断信息，不据此换模板 | `JobNotifier.status` |
| 实时通知被关 | “正在处理”里给出重新打开的入口 | `QueueNotices.kt` |

协议值不硬编码成 3：岛模板（OS3）的字段要以审核通过后小米确认的方案为准。

## 2. 为什么现在拿不到权限

小米的接入流程要求：

1. 开发者实名认证（人工审核 1–3 个工作日）。文档只给了企业认证指南；没写个人开发者不行，但大概率需要企业主体。
2. 应用在小米开放平台上架（应用审核 1–3 个工作日）。**只有在架应用能开通超级岛**，海外应用不能用国内平台能力。

本应用目前只在 GitHub Releases 发布，不在小米应用商店，所以第 2 步过不去。要走审核，先要决定：

- 是否上架小米应用商店（上架包要和 GitHub 版用同一签名，否则用户不能互相覆盖安装）；
- 用什么主体认证。

在这之前，标准实时通知已经能让进度显示在 HyperOS 3/4 的岛和锁屏上（是否上岛以真机为准，见 [VERIFY.md](VERIFY.md)）。

## 3. 流程（上架之后）

1. 小米开放平台控制台：开发 → 开放服务 → 小米超级岛 → 服务启用。填联系人，配证书指纹（release 和 debug 指纹都可以配，鉴权看 APK 签名）。
2. 清单加两项（拿到 appid 后再加，现在不加）：

   ```xml
   <meta-data android:name="com.xiaomi.xms.APP_ID" android:value="<appid>" />
   <meta-data android:name="com.xiaomi.xms.BUILD_TYPE_DEBUG" android:value="false" />  <!-- debug 签名的包设 true -->
   ```

3. 场景预审：选场景类型（没有合适的选“（其他）”），文字描述场景和核心信息，驱动方式选“客户端”（应用在后台保持运行：导出期间有前台服务）。运营、促销、借款类内容会被拒。
4. 正式方案审核：从通知开始到结束的每个变化节点、节点信息和效果图（见第 4 节）。
5. 白名单联调：按 OAID 加测试机，每个应用最多 10 台，每次 30 天有效，白名单机跳过本地权限检查。要 OS2 焦点通知的测试包，另发邮件（第 5 节），附场景审核通过截图和测试机系统版本截图。
6. 线上验证：提交正式环境 APK 和每个场景的触发方法。OS2 焦点通知和 OS3 岛要合进同一个 APK 一起验。通过后灰度，约 7–15 天到 100%。
7. 权限有效期到当年 12 月 31 日，到期前 2 周重新申请。不收费。

## 4. 场景说明（草稿，可直接填进预审和方案审核）

**场景名称**：照片后台冲洗进度

**场景类型**：其他（工具类，本地图片处理进度）

**驱动方式**：客户端。处理全部在手机本地完成，不联网，没有推送。

**说明**：用户在编辑器里点“保存”或“极致渲染”后，照片进入后台队列，按胶片模拟参数逐张渲染并保存到相册。单张需要几秒到几分钟（全分辨率可能更久），用户通常会切到别的应用。焦点通知 / 岛显示当前这张的进度和整个队列的剩余时间，点击回到应用的“正在处理”列表。

| 节点 | 出现 / 变化时机 | 显示内容 | 刷新频率 |
|---|---|---|---|
| 开始 | 队列从空变为有任务，前台服务启动 | 标题“正在冲洗 〈文件名〉”；进度 0%；剩余时间“约 N 秒 / 分”；岛小区域：应用图标，大区域：百分比和剩余时间 | — |
| 进行中 | 每张照片的处理阶段（读取、解码、冲洗、编码、校验） | 阶段名 · 剩余约 X · 还有 N 张；进度 0–100% | 最快每 0.9 秒一次，只在百分比或剩余时间变化时更新 |
| 下一张 | 一张保存完成，下一张开始 | 标题换成下一张的文件名；“2 / 5”这类序号 | 每张一次 |
| 暂停 | 系统限制后台时间（Android 15+ 前台服务时限）或拒绝后台启动 | 焦点通知结束，改发一条普通通知“后台处理已暂停 · N 张待处理，打开应用即可继续” | 一次 |
| 结束 | 队列清空 | 焦点通知消失，改发一条普通通知“已冲洗完成 N 张”（或失败张数），10 分钟后自动消失 | 一次 |

- 预计持续时长：单张数秒到约 5 分钟；一批几十张可到半小时以上。
- 不含广告、营销、导流内容；点击只回到本应用的任务列表。

**产品方案材料（要另外准备）**：
- 触发截图：编辑器“保存”菜单、“正在处理”列表。
- 效果图：每个节点在状态栏、通知中心、锁屏、息屏、岛（摘要态和展开态）的样子。可以先用 HyperOS 3 真机上的标准实时通知截图，再按小米模板库画岛的展开态。
- 交互：点击 → 打开应用“正在处理”；岛上不放按钮（取消在应用里做）。

## 6. 审核通过之后要改的代码

- 清单加第 3 节的两个 `meta-data`。
- 按小米确认的模板写 OS3 岛参数（`protocol` 取方案里定的值），仍按 `notification_focus_protocol` 只在支持的系统上发；标准实时通知保留，作为其他手机和未授权时的路径。
- `canShowFocus` 为真后，在真机上对照 [VERIFY.md](VERIFY.md) 的“小米适配”一节再验一遍。
