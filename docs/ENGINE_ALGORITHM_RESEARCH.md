# 引擎算法复核与 Android 执行方向

日期：2026-11-08。共创：**GPT（OpenAI，AI 助手）**。
上游固定为 `a46627d250545a394ca21522f8a28b0fb89e4c42`，加本仓库补丁。

本记录按源码和实验判断问题，不以作者背景判断正确性。区分三件事：保持已有图像的执行优化、
会改变图像的数学修正，以及尚需光学或实拍参考才能确认的模型选择。没有修改胶片、相纸或光谱材料数据。

## 1. 已落地的等价优化

### 曲线预计算

上游 `view_process.cpp` 的曲线函数每次采样都重新构造差分和斜率数组，Android 原实现沿用了这个结构。
一条曲线生成 256 个采样时，相同的系数被重复计算数百次。

`app/src/main/cpp/tone_curve.hpp` 将系数准备与采样分开。仍使用 double，保留依次修改相邻斜率的
限制循环、区间比较、Hermite 表达式和最终 float 转换；没有先展开多项式、改变加法结合顺序或降低精度。
1,787 条曲线、1,148,285 个采样的 double 和 float 字节与冻结旧实现一致，覆盖平台、反向、交替、
极近控制点、2 至 256 点，以及每个控制点两侧的相邻浮点数。

### FIR 半径查询

上游 `Blur::fir_radius` 为查询 halo 而调用 `gaussian_kernel_1d`，分配整个数组、计算指数、归一化后丢弃。
补丁 `0018` 抽出与核构建器共用的半径函数，保留 `size_t(truncate * sigma + 0.5)` 的舍入。
3,600 个边界样本通过核值和半径比较；拒绝堆分配时，真实 `Blur::fir_radius` 仍成功。
非正 sigma 在转换为无符号半径前返回 identity，避免旧代码先计算不合理长度再检查。

### 输出端按条带转换

`Rgba16Rows` 保持完整画布坐标、同一份蒙版和灰尘几何，只转换编码器请求的行。
TIFF 工作线程各自持有条带缓存，完成转换、水平 predictor 和 deflate，再按原顺序写入。
保持 32 行 strip、压缩级别、ICC、目录布局和两次 UNORM16 量化边界。

4097 × 3073 时，省掉的完整 RGBA16 副本为 100,720,648 字节；至多 4 个转换缓存的像素载荷
为 4,195,328 字节。还需计入原图、引擎结果、压缩缓存和几何数据。
独立进程测试的峰值 RSS 为 312,696 → 221,044 KiB，约下降 29.3%；完整 TIFF 相同。
这是云端测试程序的进程峰值，不能直接推算手机 App 的同等降幅。

## 2. 递归模糊的末端条件存在缺陷

真实 Vulkan 着色器 `spk_iir_df_acc.comp` 使用 Young–van Vliet 三阶正反向递归。
正向扫描后，反向扫描的三个状态全部初始化为最后一个正向输出：

```text
xn = forward[last]
reverse_state = {xn, xn, xn}
```

这相当于假定后续正向输出立刻变成常数，没有纳入正向递归尾部的衰减过程。
Triggs / Sdika 的原论文专门分析了该启发式，并给出线性状态转换；不能把更高算术精度当作边界条件的修复。

### 实际 GPU 证据

`tools/native/blur_boundary.cpp` 调用真实 `Blur::gaussian` 和 Vulkan 核。
513 点信号在原方向与翻转后再翻回之间的最大绝对差：

| sigma | 信号 | 左右翻转差 |
|---|---|---|
| 3 | 末端 8 点为 1，其余为 0 | 0.0319282412529 |
| 6 | 同上 | 0.341810166836 |
| 24 | 同上 | 0.598055927083 |
| 96 | 从 0 到 1 的线性斜坡 | 0.20117777586 |

常量保持正常，FIR 路径的翻转差约为 1e-7 量级。这里的误差来自固定诊断信号，不代表任意照片的误差比例。
另一个指标比较“原长信号”和“常量延拓后裁切”。FIR 原本使用 reflect，延拓测试使用 constant，二者的边缘
差异不是缺陷证据。CSV 单独给出内部有效样本数；没有有效内部区域时记录 `nan`，不将其记成零误差。

### 独立数学候选

`tools/native/iir_boundary_reference.cpp` 使用上游实际 `yvv_coeffs`，按论文的线性转换计算
三个末端状态，包含非零常量延拓的 DC 补偿。系数转换用 long double，扫描用 double。
参考实现显式延长输入、继续正向递归，再反向扫描，不调用候选转换矩阵；延拓长度加倍后还要确认参考收敛。

120 组样本覆盖长度 1、2、3、17、513，sigma 3、6、24、96，以及常量、斜坡、阶跃、脉冲和 HDR 交替信号。
候选相对延拓参考的最坏绝对误差为 `4.42701431069e-11`，左右翻转最坏差为 `1.02308161942e-10`。
将同一 double 扫描按 1、2、7、32、257 点分段、保留状态，结果与连续扫描逐字节相同。

这只是 CPU 候选，未替换产品 shader。它使用完整测试向量，也没有实现 GPU 外存读写。
移植前还需验证 float pair 精度、前向平面的 float32 舍入、混合通道、累加、两遍方向及 Adreno/Mali。
更正边界会有意改变旧桌面输出，必须作为显式的算法修正验收，不能混进“逐字节等价”的优化。

## 3. FIR / IIR 切换还存在核形状差异

上游在每个通道的 sigma 小于 3 时使用截断 FIR，达到 3 时切换至递归近似。
`blur_boundary --kernel` 将脉冲放在足够宽的平面中心，用真实 GPU 输出测量能量、质心和均方根宽度；
与按同一 sigma 采样、归一化的离散高斯比较。边缘距离超过 32 sigma，避免将末端缺陷混为核形状误差。

| 请求 sigma | 方法 | 测得宽度 | 与离散高斯的 L1 差 |
|---|---|---|---|
| 2.999 | FIR | 2.97457687935 | 0.00292118369506 |
| 3 | IIR | 3.29951599745 | 0.054754067498 |
| 6 | IIR | 6.65543009017 | 0.0447469968453 |
| 24 | IIR | 25.9438559595 | 0.0188185946853 |
| 96 | IIR | 96.6141015834 | 0.0633847281546 |

跨阈值时测得宽度约增加 10.9%，而请求 sigma 仅相差 0.001。这说明切换并不只改变执行时间。
测试中总能量接近 1，因而主要是形状和宽度变化。L1 差是核的指标，不是照片颜色误差百分比。
sigma 0.5 的离散采样宽度本来就不等于连续高斯的 sigma，不能据此判断实现错误。

这是近似模型的局限，尚不能仅凭它断言某种照片“不像胶片”。要评估更精确的导出模式，可对照：
更大截断半径的直接 FIR、FFT 卷积、重拟合递归系数及原有近似。它们需要分别验证 PSF、频率响应、
多尺度混合顺序、运行时间和内存；改变系数或阈值后必须重做桌面与光学参考的验收。

原始数据：
[`validation/android-engine-blur-kernel-2026-11-08.csv`](validation/android-engine-blur-kernel-2026-11-08.csv)。

## 4. 用时间换内存的执行条件

分块能够保留算法，前提是保存每种操作的真实依赖；“分图层”不能自动使递归或全局过程独立。

| 运算 | 可实现的执行方式 | 需要验证的契约 |
|---|---|---|
| 光谱积分、矩阵、曲线、LUT | 按像素块执行同一算术 | 顺序、精度、LUT 插值和全局坐标 |
| 连续 FIR | 累加相继阶段的 halo，只写中央有效区域 | 原边界模式，不能在每块边缘重新 reflect |
| 递归 IIR | 正向扫完整条线，保存状态和中间结果，再反向扫 | 三项递归状态、正反方向、原有 float32 存储边界 |
| 自动曝光和全帧统计 | 先完整统计，再使用同一统计值分块渲染 | 归约顺序和曝光值，不能改用缩略图冒充严格结果 |
| 随机颗粒 | 保留随机种子与全局索引，再分块消费 | 分布、空间频谱、层顺序和确定性，避免每块重复种子 |
| 大图驻留 | 主机内存或文件中间存储，GPU 只保留当前工作集 | 单缓冲 range、对齐、池中活跃缓冲和读回成本 |
| 文件输出 | 按行或条带转换、压缩、写入 | 最后不能重新拼成完整调整帧；本轮 TIFF 已完成此段 |

当前执行器仍物化 source、negative 和输出平面；`choose_strip_height` 没有使用真实字节预算。
单纯缩小 dispatch 或 `strip_rows` 不能绕过整幅 SSBO 的绑定范围。
前期 6016 × 4016 输入在严格 128 MiB range 下仍失败的事实保持有效，本轮没有声称解决。

另一个已确认的执行缺口在 `storage_probe.cpp`：等待返回 `VK_TIMEOUT` 后释放提交引用的缓冲，
而 timeout 并不表示 GPU 已完成。需要把在飞资源保留到 fence 完成或设备丢失，再销毁设备对象。
本轮未修改探测器，也不以提前释放或删掉同步来换取表面速度。

## 5. 证据与后续优先级

先完成真实工作集预算和跨块递归状态，再考虑减少提交次数；后者必须建立在在飞资源和描述符的正确生命周期上。
边界修正与更高保真核作为独立的算法选择验证，保留兼容基线。光谱材料、颗粒的物理参数是否准确，仍需
独立实测参考，不能从“跑得通”或与旧版本相同推导出来。

本轮环境为 x86_64、GCC 11.4、Linux llvmpipe（LLVM 15.0.7）。编译 Android arm64 与真机执行是两种不同证据。
第二批尚无第二台云机或 Android 真机复证，不能宣称任意设备逐位相同。
GitHub 的独立 Ubuntu 24.04 runner 已通过严格 / 默认数值测试、完整 APK、单元测试、16 KB 对齐及截图构建；
它没有执行这里的 GPU 诊断，不能代替第二个 GPU 环境的算法复证。
