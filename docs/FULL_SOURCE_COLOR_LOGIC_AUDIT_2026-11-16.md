## 色彩数值核验

### 插值的独立数学参照

新增 `tools/native/lut_independent_oracle.cpp`，用 long double 与 Cramer 法则求
四面体重心坐标，独立于生产代码的排序权重公式。每个编译器验证 174,909 个输入，
覆盖边长 2、3、5、17、33、65、129，非线性随机表、六种四面体顺序、相等坐标、
边界相邻浮点数、非单位及极宽定义域、NaN 和无穷输入。
GCC 11、Clang 14、GCC 14 的 ASan / UBSan 检查均通过；最大绝对差分别为
原始链 `2.98023e-8`、网格 `1.32783e-7`，16 位量化最大差均为 1 个码值。
新增参照已接入常规 native 回归入口。

### 原始 CUBE 链与输出色彩管理

从当前 Kotlin 实现生成参考，实际 C++ 求值逐像素对照：sRGB 与 ProPhoto 各
16,384 个离网格输入，GCC 11 和 Clang 14 均通过地址及未定义行为检测。
sRGB 最大通道差 `1.19209e-7`，ProPhoto 为 `5.96046e-8`，16 位最大差均为 1。
129 级交替细节的原生格点均保留。超过包内原文上限的文件仍会走有限兼容网格，
该原生容量结果不等于所有大文件导入都已无损。

实际生产 Kotlin ICC、输出转换和 TIFF 写入另以独立 LittleCMS 对照，
四份 TIFF 共 4,420 个像素。相对参照矩阵的最大码值差 `0.4993160301`，
最大像素 XYZ 差 `1.1880089e-5`，整幅与不同行条带写入逐字节一致。
错误 gamma 2.2 的负对照拒绝 1,529 个样本，错误适应矩阵拒绝 2,214 个样本。
其中 2,860 个样本落在裁切条件，近零区间为 0；不能据此扩展为所有暗部、所有 ICC
或全色域场景已验证。此集成核验复用了有摘要记录的未修改宿主引擎静态库。

### 87 套内置方案

完整配方逐套检查与 SPK 往返通过。新增 87 × 87，即 7,569 种有顺序的切换组合，
逐项比较目标配方、精确渲染数组、照片几何、RAW 开发及蒙版保留，并检查重复应用的幂等性。
可设置 `SPK_BUILTIN_EVIDENCE_DIR` 从实际 Kotlin 模型导出每套完整参数和渲染数组，
再由 `tools/native/run_builtin_schemes.sh` 接入正式 JNI 渲染路径。
实际 JNI 以 96 × 64 的合成输入逐套核验：sRGB 与 Display P3 共 174 组，
每组 24,576 字节的预览与同尺寸主渲染完全一致；每个输出空间均有 87 种不同的
结果摘要，父照片像素和配方不变，全部会话已释放。ASan / UBSan 通过；
此引擎集成关闭 Vulkan 驱动泄漏检测，不把它计为完整驱动泄漏检查。
初版补充探针的 API 命名和断言字符串类型错误导致编译失败，修正后才取得上述结果。

这些检查证明已覆盖输入中的计算与状态一致性。缺少同场景 RAW、官方输出及标准色卡
参照的胶片乳剂和厂商风格，仍不能宣称“原厂同色”或给出实拍匹配 DeltaE。
相同尺寸合成输入的逐字节一致，也不代表不同预览尺寸的颗粒和空间效果逐像素相同。

别名表先设主名再读取别名的顺序。所审查入口中未再复现额外缺陷；诊断轨迹与依赖
约束均保留，不能推断任意外部输入或未来修改都安全。已有三方无效赋值提示继续保留。

完整回归同时覆盖以下行为：

- 精密刻度：0.01 EV、负号与 Unicode 负号、非法小数、越界输入、可修正输入、取消释放交互。
- 曲线与色轮：滑动滚页、拖动取消、禁用或移除、尺寸变化、通道切换及双回调释放。
- 编辑与保存：撤销重做候选不提前移动历史、跨照片保存、写入失败重试、后台与退出刷新。
- 选择预览：配方含 LUT、蒙版、相纸及色域，旧请求不能发布，新来源与缓存隔离。
- 现有渲染回归：RAW 边界、位流、量化、行式输出、Vulkan 失败恢复及非有限输出拒绝。

自动交互检查不能代替手机输入法、系统取消、主观触觉和长时间热负载检查。
